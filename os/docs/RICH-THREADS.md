# CopilotKit Rich Threads and the agent computer

OpenFuse uses `@copilotkit/react-native/headless` for its custom native and web interface. Chat messages, tool cards and task-linked documents render through CopilotKit's AG-UI agent and tool hooks.

## Rich Threads (saved in Debo's own database)

Conversations are stored by Debo, in the same Postgres (or embedded PGlite) as everything else. No CopilotKit Intelligence account, project key or outside service is used, and no chat content leaves the server just to be stored. If `CPK_INTELLIGENCE_API_KEY` is still set in the environment it is ignored, and the server logs a note at startup.

### What the runtime supports (`@copilotkit/runtime` 1.70.1)

- Passing `intelligence` to `CopilotRuntime` switches to `CopilotIntelligenceRuntime`. It forbids a custom `runner`, talks to the hosted service over WebSocket, and every thread route (`/threads`, rename, archive, messages, subscribe) calls that service. There is no storage adapter for it.
- Without `intelligence` it is `CopilotSseRuntime`, which accepts a custom `runner` (the exported `AgentRunner` class: `run`, `connect`, `isRunning`, `stop`). The default `InMemoryAgentRunner` loses everything on restart, is one process-wide store not scoped by owner, and offers only an unscoped read-only list. Rename and archive are not available in this mode (mutations are reported as unsupported by `/info`).
- So Debo supplies its own `AgentRunner` and its own thread routes.

### Design

- `apps/server/src/thread-runner.ts`: `DatabaseAgentRunner` runs the agent, streams events live, and saves each finished run. `connect` replays saved events and joins a reply still streaming. Stop works as before. The signed-in owner comes from the request through `AsyncLocalStorage`; with no owner the runner refuses to act. Live state is keyed by owner and thread, so one person cannot replay or stop another person's thread.
- `apps/server/src/threads.ts`: `ThreadStore` over the `records` table, always filtered by owner. Kinds: `threads` (name, archived, timestamps), `thread-history` (compacted AG-UI events and the message list), and `conversation-settings/main` (the main chat id).
- Routes (all behind the normal session check): `GET /api/main-thread`, `GET /api/threads?includeArchived&limit&cursor`, `PATCH /api/threads/:id` (rename), `POST /api/threads/:id/archive`, `POST /api/threads/:id/restore`, `GET /api/threads/:id/messages`. The CopilotKit routes that need Intelligence (`/api/copilotkit/threads...`) stay closed.
- A new thread is named from the first words of the first message, locally. A name the person chose is never overwritten.
- App: `apps/mobile/src/thread-list.ts` replaces CopilotKit's `useThreads` with a small hook over these routes. Replay still uses `copilotkit.connectAgent`, now answered by the runner above.

The queue behavior is unchanged: follow-ups wait in a visible, removable queue in the open app, and Stop requests `copilotkit.stopAgent`. Rich tool messages keep their task IDs, and expiring file and preview URLs are generated by the server, not stored in threads. `/api/conversation` is still the fallback single-conversation store.

Limits: a reply that is streaming when the server stops is not saved (the run's events are written when it finishes). Replay history is kept as one compacted row per conversation, which is fine for normal chats and will want paging for very long ones. Deleting a conversation is supported in `ThreadStore.remove` but has no screen yet.

## Agent computer

The Computer control below the avatar opens a persistent workspace with browser sessions and files. Browser cards show actual worker screenshots; **Open browser** opens the existing interactive console for takeover. PDFs open in the native/web readers. Tasks can read public pages, monitor changes and collect PDFs using the same worker.

Opening a session renews its short-lived console access. **Refresh connection** renews access without navigating; **Reopen** keeps the saved profile and uses the address in the input. The console reports live/disconnected state, preserves unsent text after an error, and pauses preview polling when hidden. Closing a session retains its profile and downloads.

Run the browser worker using the `BROWSER_WORKER_URL` and `WORKER_TOKEN` setup in the [README](../README.md). Browser profiles persist on disk. The optional [Linux computer](COMPUTER.md) adds real command execution, saved output, editable files, and PDF transfer. CopilotKit's built-in conversation and task-worker tools use this same computer; remote AG-UI backends must supply their own equivalent tools. Interactive reservations still require user takeover; autonomous booking, checkout, graphical desktops and per-user VM isolation are not implemented. The OpenBot adapter remains an extension point for other computer backends.

## Validation scope

`tests/threads.test.ts` drives the real CopilotKit runtime (`run` and `connect`) and Debo's thread routes in-process. It covers creation, listing and paging, owner isolation, rename, archive, restore, replay, history surviving a store restart, and a fetch spy showing no outside call. It does not cover the native or web screens on a device.
